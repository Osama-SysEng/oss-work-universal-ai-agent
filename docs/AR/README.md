# إصدار OSS-Work الآمن

هذا الإصدار هو **أساس محلي أولًا لنظام متعدد الوكلاء**. الأولوية فيه للسياسات الصريحة، وحدود الصلاحيات، والنتائج القابلة للاختبار، وتسجيل التدقيق، والتحكم في الموارد، بدل الادعاءات غير القابلة للإثبات مثل الوصول المجاني الدائم إلى النماذج التجارية أو القدرة غير المحدودة أو الحصانة من الاختراق.

> لا يوجد نظام يمكن ضمان أنه غير قابل للاختراق أو أنه لن يتأثر بأي عدد من المستخدمين. الأمان الحقيقي هو تقليل المخاطر عبر التصميم، والعزل، والتحديث المنضبط، والمراقبة، والاختبارات المستقلة، وخطة الاستعادة.

## الحالة الفعلية للوظائف

يوفر المشروع دورة حياة صحيحة للوكلاء، وعقودًا typed للطلبات والقرارات، وعمليات ملفات محصورة داخل جذر مسموح، وذاكرة SQLite محلية باستعلامات parameterized، وفحوصًا محلية للأنماط الخطرة، وتنسيقًا محدودًا للمهام، وحدودًا محاكاة للمتصفح والتكاملات الخارجية، ومتحققًا للمرفقات والتحديثات دون تثبيت تلقائي.

| الوظيفة | الحالة | الحد الأمني |
|---|---|---|
| تفكيك المهام | مفعلة | خمسة وكلاء كحد أقصى للطلب |
| عرض وقراءة والبحث في الملفات | مفعلة | داخل `OSS_WORK_ALLOWED_ROOT` فقط |
| الكتابة والحذف والنقل | تتطلب موافقة | داخل الجذر؛ حذف المجلدات غير مدعوم |
| توليد ومراجعة الكود | مفعلة | لا يوجد تنفيذ داخل العملية المضيفة |
| أتمتة المتصفح | محاكاة فقط | لا تسجيل دخول أو تصفح أو إرسال نماذج |
| التكاملات الخارجية | محاكاة فقط | لا مفاتيح حية ولا إرسال خارجي |
| الفحص الأمني | فحوص محلية | ليس بديلًا عن CodeQL أو Snyk أو ZAP أو اختبار اختراق |
| التحديث وتنزيل المهارات | معطل | التحقق من artifact فقط دون تثبيت أو فك آمن تلقائي |
| الذاكرة | SQLite محلي | استعلامات parameterized ونطاق لكل مستخدم |
| البصمة السلوكية | معطلة افتراضيًا | إحصاءات مجمعة داخل الطلب فقط |

## التشغيل

يتطلب المشروع Python 3.11 أو أحدث ولا يحتاج إلى حزم خارجية إلزامية.

```bash
python -m venv .venv
. .venv/bin/activate
python -m pytest
python -m core.main --version
python -m core.main "راجع هذا الكود أمنيًا"
```

يمكن تحديد مجلد البيانات عبر `OSS_WORK_DATA_DIR` وجذر الملفات عبر `OSS_WORK_ALLOWED_ROOT`. لا تضع مفاتيح الخدمات أو كلمات المرور في الملفات المصدرية أو السجلات أو `.env.example` أو الأرشيف النهائي؛ استخدم مدير أسرار في بيئة النشر.

## نموذج الموافقة

امتلاك الوكيل لقدرة معينة لا يمنحه الإذن تلقائيًا. تتطلب عمليات التعديل قيمة `approved` صريحة، كما يجب أن تسمح السياسة نفسها بنوع العملية. وتبقى العمليات الخارجية محاكاة فقط حتى إنشاء موصل مستقل يخضع للمراجعة.

يتضمن كل قرار التصنيف، وإشارات المصدر، والشرح، والإجراء البشري المقترح، وقرار السياسة، وحقل `external_action_attempted` الذي يجب أن يبقى `false` في هذا الإصدار.

## قابلية التوسع

المنسق الحالي محدود ومتزامن، وهو أساس قابل للاختبار وليس ادعاءً بالتزامن اللانهائي. للوصول إلى تشغيل إنتاجي، يلزم إضافة مصادقة، وطابور مشترك، وعزل للعمال، وحصص لكل مستخدم أو مؤسسة، واتصال مضبوط بقاعدة البيانات، وضغط خلفي، ومراقبة، ونسخ احتياطية، واختبارات حمل مرتبطة بهدف خدمة محدد.

## متطلبات التفعيل الإنتاجي

قبل تفعيل أي تكامل حي أو تنفيذ كود، يجب إجراء مراجعة أمنية خاصة بكل مزود، وتحديد الموافقة وسحبها، والتحقق من توقيع payloads، ومنع التكرار، وعزل العمال، واختبار التراجع في بيئة staging. هذه الخطوات غير مخفية خلف مثبت بنقرة واحدة عمدًا.
