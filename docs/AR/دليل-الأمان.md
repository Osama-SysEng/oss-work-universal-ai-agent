# دليل الأمان — OSS Work / OS_V1

## هدف الأمان

يحمي OS_V1 **ملفاتك وجهازك من أخطاء الوكيل**، ويمنع الوكيل من التصرّف باسمك دون قرار منك.
لا يدّعي حماية نظام غير مُرقَّع، ولا جهاز مخترق، ولا مسؤول خبيث، ولا محوّل لم يُراجَع بعد.

النظام يملك وصولاً حقيقياً إلى ملفاتك، لذلك طبقة الأمان **إلزامية** (المواصفة §19): تقع تحت كل
مكوّن آخر، **ولا يعدّلها النظام نفسه**.

## حدود الثقة

| الحد | التحكم الافتراضي | المطلوب قبل النشر كخدمة |
|---|---|---|
| مدخل المستخدم ← عقد المهمة | طول ونوع + **مصدر** + **درجة ثقة** لكل مدخل | هوية موثّقة وصلاحيات لكل مستأجر |
| الوكيل ← نظام الملفات | حصر المسار داخل الجذور الممنوحة | حساب نظام مستقل + جذر لكل مستأجر |
| الوكيل ← تنفيذ الكود | sandbox بلا شبكة وبلا أسرار موروثة + مهلة | سجن على مستوى النظام (حاوية/آلة افتراضية) + حدود CPU والذاكرة + منع الصادر |
| الوكيل ← تشغيل البرامج | قائمة سماح صريحة + `cwd` محصور + بيئة مفرّغة | حساب مستقل + تدقيق لكل برنامج |
| الوكيل ← الخدمات الخارجية | قارئ قراءة فقط | OAuth وخزنة توكنات + موافقة + تحقّق توقيع + تكرار آمن + مفتاح إيقاف |
| الوكيل ← طبقة الأمان | **مرفوض** ببوابة الترقية | مراجعة خارجية للبوابة نفسها |
| مخزن الذاكرة | 4 أنواع منفصلة + نطاق لكل مستخدم + استعلامات مُعامَلة | تشفير عند التخزين + سياسة احتفاظ + اختبار استعادة |
| سجل التدقيق | سلسلة تجزئة: أي تعديل يُكتشف | خادم تدقيق للقراءة فقط + احتفاظ مُراجَع |
| أرشيف المزامنة | مشفّر بـ DPAPI | مفاتيح بيد المستخدم + هدف تخزين مُدقَّق + استعادة مُختبَرة |
| سجل التراخيص | كل نموذج/بيانات/أداة بمصدرها ورخصتها | مراجعة قانونية لقائمة المراجعة |

## حالات الإساءة التي يرفضها التصميم

- **اختراق المسارات** — كل مسار يُحلّ ويُفحص مقابل الجذور؛ وما خرج منها يُرفض بسببه.
- **عمل مدمّر بلا قرار** — الحذف والإرسال والدفع والنشر وتغيير الإعدادات تنتظر موافقة صريحة، والموافقة تُستهلك مرة واحدة.
- **حقن التعليمات** — محتوى الملفات والمواقع والأدوات والمستودعات **بيانات**: يُوسم، ويفحص بحثاً عن جمل تشبه التعليمات، ولا يدخل قناة التعليمات. **طبقة التنفيذ** هي ما يوقف التحوّل من نص إلى فعل.
- **تنفيذ ديناميكي على المضيف** — لا `eval` ولا `exec` ولا shell مبني من نص المستخدم. الكود المولَّد يعمل في الـsandbox.
- **توسّع بلا حدود** — عدد الوكلاء وسقف السياق وحجم المخرجات وحجم الملف: كلها حدود صريحة.
- **أسرار في السجلات** — المفاتيح التي تحمل بيانات اعتماد تُستبدل قبل الكتابة، في السجل التشغيلي وفي سجل التدقيق.
- **إفساد ذاكرة صامت** — الوقائع والخبرات والمهارات والافتراضات أنواع منفصلة، ولقطة الذاكرة تُستعاد بخطوة.
- **تعديل الحُرّاس ذاتياً** — طبقة الأمان والأذونات والسجل ومفتاح الإيقاف واختبارات المُتحقِّق مرفوضة ببوابة الترقية.
- **تحقّق يوافق نفسه** — المُتحقِّق يشتق الحقائق من المخرجات لا من ادعاءات المُستدلِّب. ومِعول التقييم **يزرع أخطاءً معروفة** ويتأكد منcaughtها، **مع حالة ضابطة** حتى لا يمرّ مُتحقّق يرفض كل شيء.

## المخاطر المتبقية (معلنة لا مُنكرة)

- الكود **محلي** لا خدمة متعددة المستأجرين: لا API شبكي، ولا طابور موزّع، ولا قاعدة عالية التوفر.
- الـsandbox يمنع الشبكة على **أبناء Python**؛ كود أصلي أو وقت تشغيل آخر قد يتجاوزه.
- الـAPI المحلي **بلا مصادقة** — مربوط بـ`127.0.0.1` ويجب أن يبقى كذلك.
- النموذج 3B محلي: مخرجه ليس مخرج نموذج forefront، والواجهة تذكر أيّ نموذج أنتج الإجابة.
- فحص حقن التعليمات **heuristic** — يمسك الأنماط الشائعة، وليس إثباتاً.
- **حساب النظام المستقل لم يُنشأ**: حتى ذلك الحين الحصر على مستوى التطبيق لا على مستوى الحساب.
- **السعة غير مُثبَتة**: فئات الجهاز أهداف تخطيط، والأرقام في README قياسات لجهاز واحد لا أهداف خدمة.
