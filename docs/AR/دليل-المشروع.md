# OSS Work / OS_V1 — دليل المشروع بالعربية

## ما هو هذا

وكيل ذكاء اصطناعي محلي موحّد، يعمل على جهازك بلا مزوّد ولا مفاتيح ولا إنترنت في المسار الأساسي.
المستخدم يرى نموذجاً واحداً باسم **OS_V1** له وضعان:

- **Plan (تخطيط):** يحلّل ويتوقّع ويقترح خطة. لا ينفّذ شيئاً.
- **Build (تنفيذ):** ينفّذ الخطة المعتمدة، يتحقق من كل خطوة، ثم delivers النتيجة مع سجلها.

الفكرة المركزية: استبدال «نموذج لغوي يكتب إجابة مقنعة» بـ«نظام يفكّر ويتوقّع ويقرر ويتحقق ثم ينفّذ».

## الطبقات الست (القسم 8 من المواصفة)

| الطبقة | ماذا تضمن |
|---|---|
| الإدخال | كل مدخل يحمل مصدره ودرجة ثقته، والمدخل التالف يُبلَّغ عنه ولا يُتجاهل |
| نموذج العالم والذاكرة | كل فعل يُتوقَّع قبل تنفيذه ويُقارن بما حدث فعلاً |
| الاستدلال | الفرضيات تُختبر بأدوات حقيقية، وما تناقضه الأدلة يُسقَط |
| القرار | الخيارات تُقاس، والنظام يمتنع أو يسأل حين لا يكفي الدليل |
| التحقق | فحوص مستقلة على المخرجات، لا على الاستدلال |
| التنفيذ | كل فعل له إذن وسجل سجلّ ومسار تراجع |

## النظامان

- **System One (SOM):** قرارات سريعة منظّمة (اختيار / درجة / نعم-لا) باحتمالات معايرة وأثر تفسير.
  يعمل افتراضياً بقواعد شفافة، ويدعم محوّلاً لنموذج Laya إن كان مُخدَّماً محلياً.
- **System Two (LLM):** التخطيط والتوليد عبر محرك llama.cpp المحلي. لا يُستدعى إلا عند الحاجة إلى توليد أو حين يمتنع SOM.

## الوكلاء الـ300

30 مجالاً × 10 تخصصات. لكل وكيل أدوات مسموحة، مستوى خطورة، قواعد تحقق، قالب خطة، وموجّه.
التفصيل: [`docs/AGENTS.md`](../AGENTS.md).

```bash
oss-v1 agents --search security
oss-v1 agent A153
```

## الذاكرة (القسم 14)

أربعة أنواع لا تختلط: **وقائع** (محقّقة) · **خبرات** (ماذا جرّب وماذا حدث) · **مهارات** (إجراءات قابلة لإعادة الاستخدام بشروطها واختبارها) · **افتراضات** (موسومة كافتراضات وقابلة للسحب، لا تُعامَل كوقائع).

كل الذاكرة محلية، مُصدَّرة بإصدارات، ويمكن للمستخدم تصحيحها أو حذفها أو التراجع عنها.

## الأمان (القسم 19)

- أذونات صريحة (ملفات / شبكة / برامج / إجراءات غير قابلة للتراجع) ويمكن سحبها.
- موافقة بشرية إلزامية لكل فعل غير قابل للتراجع (حذف، إرسال، دفع، نشر، تغيير إعدادات).
- سجل تدقيق بسلسلة تجزئة: أي تعديل يكسر السلسلة ويُكتشف.
- مفتاح إيقاف فوري يوقف كل شيء.
- محتوى الملفات والمواقع والأدوات يُعامَل كبيانات لا كتعليمات.
- الأسرار لا تُخزَّن نصاً صريحاً (DPAPI على ويندوز).
- طبقة الأمان والأذونات والسجل ومفتاح الإيقاف واختبارات المُتحقِّق **لا يعدّلها التطوّر الذاتي**.

## التعلّم الذاتي (القسم 15)

حلقة: سجّل ← تعلّم ← اسأل ← اختبر (بوابة تجميد) ← رقِّّ (تراجع بخطوة). أي تحديث لا يجتاز مجموعة
الاختبارات المجمّدة لا يُرقّى.

## جلسات التدريب (القسم 16) والتخصيص الأسبوعي (القسم 17)

- **جلسة التدريب:** تبني نفس المشروع مرتين — مرة من README فقط، ومرة بتحليل المخرجات (REA) — ثم
  تقارن النتائج وتقيس نسبة النجاح والفرق الزمني والأخطاء المتكررة. الكود المُستنسخ يعمل داخل
  sandbox بلا شبكة، ولا يُنسخ كود المشروع الأصلي أبداً.
- **التخصيص الأسبوعي:** يبني النظام ملف عمل عن أسلوب المستخدم (بنية، تسمية، نبرة)، ويقيس التطابق
  مع اختياراته على مهام محجوزة، ويكتب أثراً مشفّراً على الجهاز. **ملاحظة صريحة:** الأثر الحالي
  ملف تفضيلات مشفّر وليس أوزان LoRA (تدريب حقيقي يحتاج حزمة تدريب غير مضمّنة هنا).

## التشغيل

```bash
pip install -e ".[dev]"
python -m pytest tests/ -q
python -m osv1.interface.cli status
python -m osv1.interface.api        # اللوحة الحية على http://127.0.0.1:8080
```

المحرك المحلي (اختياري): `C:\tools\llama\start-engine.cmd` (المنفذ 11400).

## حدود صريحة

- نموذج 3B محلي: مهام خفيفة وقرارات؛ المهام الثقيلة تُقسَّم أو تُؤجَّل.
- المتصفح للقراءة فقط: بلا JavaScript ولا فورم ولا تسجيل دخول ولا لقطات.
- sandbox يمنع الشبكة على أبناء Python، لكنه ليس سجناً على مستوى نظام التشغيل.
- الـAPI المحلي بلا مصادقة لأنه مربوط بـ loopback فقط.
- الأرقام في هذا المستودع مقيسة، والمقاييس تُبلَّغ مع عدد العينات.
