# نموذج التهديد وحدود الإصدار

## الهدف الأمني

يحمي الإصدار الآمن مجلد البيانات المحلي ويمنع النظام من تنفيذ كود أو تثبيت حزم أو الاتصال بخدمات خارجية أو تعديل ملفات خارج الجذر المسموح دون تصريح واضح. ولا يدّعي حماية نظام تشغيل مخترق أو جهاز غير محدث أو مسؤول خبيث أو موصل خارجي لم يخضع للمراجعة.

## حدود الثقة

| الحد | الضبط الافتراضي | المطلوب قبل الإنتاج |
|---|---|---|
| إدخال المستخدم والمهام | تحقق من النوع والطول | هوية موثقة وصلاحيات لكل مؤسسة |
| الوكيل ونظام الملفات | حصر المسار بعد canonicalization | حساب نظام معزول وجذر مستقل لكل مستخدم |
| الوكيل وتنفيذ الكود | مرفوض | sandbox مستقل وحدود CPU وذاكرة ومنع خروج الشبكة |
| الوكيل والخدمات الخارجية | محاكاة فقط | خزنة رموز وموافقة وتوقيع وidempotency وإيقاف طارئ |
| التحديثات | فحص hash فقط | توقيع مصدر وSBOM ونشر تدريجي وتراجع |
| قاعدة الذاكرة | namespace لكل مستخدم واستعلامات parameterized | تشفير واحتفاظ مضبوط واختبار نسخ واستعادة |

## حالات إساءة الاستخدام

يرفض التصميم traversal للمسارات، والعمليات المدمرة بلا موافقة، والتنفيذ الديناميكي على المضيف، والتثبيت أثناء التشغيل، وفك الأرشيفات غير الموثقة، والتفويض غير المحدود، وتسجيل الأسرار أو المحتوى الخام. ويجب أن تضيف المراجعة الإنتاجية المصادقة والتفويض وفحص سلسلة التوريد واختبارات الحمل والهجوم.

## المخاطر المتبقية

النظام الحالي أساس محلي وليس خدمة متعددة المستأجرين. لا توجد فيه واجهة شبكة أو طوابير موزعة أو قاعدة بيانات عالية التوافر أو موصلات حية. لذلك لا يمكن إثبات تحمله لعدد عشوائي من المستخدمين؛ يجب تحديد هدف خدمة واختباره بحمل واقعي قبل أي ادعاء تشغيلي.
